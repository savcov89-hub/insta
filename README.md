# insta — своя выкладка Reels в Instagram

Программа выкладывает Reels в @fitness_savtsov по расписанию через официальный API Instagram,
без Metricool. Работает в GitHub Actions этого репозитория, ничего не нужно держать включённым.

## Как это работает

1. В `queue/` лежит по файлу на каждый ролик: когда выложить, ссылка на видео, подпись, пробный или обычный.
2. Каждые 10 минут запускается `publish-reels` (`.github/workflows/publish.yml`). Если до публикации
   осталось меньше 40 минут, он заранее отдаёт видео в Instagram (до публикации его никто не видит),
   ждёт обработки и выкладывает ровно в назначенную минуту.
3. Итог пишется в `status/<id>.json`: ссылка на рилс или ошибка.

Лимиты, о которых надо помнить:

- **Пробные Reels — около 10 в сутки на аккаунт.** Это потолок самого Instagram, его не обходит ни одна
  программа на официальном API. Если упёрлись, пост получает статус `cap_wait` и сам выйдет,
  когда окно освободится (проверка раз в час, не дольше суток).
- Всего через API — 100 публикаций в сутки (Instagram).
- Лимита «20 в месяц», как у бесплатного Metricool, здесь нет.

## Что нужно один раз

| Секрет (Settings → Secrets and variables → Actions) | Что это |
|---|---|
| `IG_TOKEN` | Токен Instagram из приложения Meta («API setup with Instagram login» → Generate token). Живёт 60 дней. |
| `GH_PAT` (желательно) | Токен GitHub с правом *Secrets: Read and write* на этот репозиторий. С ним `refresh-token` раз в неделю сам продлевает `IG_TOKEN`. Без него токен надо перевыпускать руками раз в 60 дней. |

Проверка токена без публикации: Actions → `check-instagram` → Run workflow.
Если указать `test_video_url`, Instagram ещё и обработает это видео, но выкладывать его программа не будет.

## Поставить ролик в очередь

Из сессии Claude с клоном репозитория:

```bash
python3 tools/enqueue.py --id appetit-v2-2110 --at "2026-10-21 18:00" \
    --caption-file podpis.txt --cover-ms 1500 video.mp4
```

- Время без пояса — Новосибирск. По умолчанию пробный Reels, к подписчикам переводится вручную
  (`--auto-share` — Instagram переведёт сам, если зайдёт; `--regular` — обычный Reels).
- Локальное видео кладётся отдельным коммитом в ветку `media/<id>`, а не в `main`, и после публикации
  ветка удаляется. Вместо файла можно дать готовую ссылку: `--url https://…/video.mp4`.
- Несколько версий в одну минуту — несколько файлов с одинаковым `--at`, они выйдут подряд за секунды.

Формат `queue/<id>.json`:

```json
{
  "publish_at": "2026-10-21T18:00:00+07:00",
  "video_url": "https://…/video.mp4",
  "caption": "Подпись с хэштегами",
  "trial": true,
  "graduation": "MANUAL",
  "cover_ms": 1500
}
```

Отменить пост до выхода: добавить в его файл `"cancel": true` или удалить файл.
Выложить один пост прямо сейчас: Actions → `publish-reels` → Run workflow → `only` = id.

Статусы: `uploading` — видео в Instagram, ждёт времени; `published`; `cap_wait` — ждёт окна по лимиту
пробных; `failed` — ошибка (текст в файле); `missed` — запуск опоздал больше чем на 3 часа, пост не выложен;
`cancelled`.

## Безопасность

Репозиторий публичный, логи Actions видны всем. Токен не печатается: программа вычищает его из любых
сообщений, а новый токен при продлении сразу маскируется. Не добавляйте в workflow `curl -v`,
`set -x` и вывод переменных окружения.

## Проверка кода

```bash
python3 -m unittest discover -s tests -v
```

Тесты гоняют программу против поддельного API Instagram и ничего наружу не отправляют.
